# Fruit Juice Storage Dataset

`fruit_juice_storage.csv` is a **synthetic dataset created for teaching** an
introductory Data Analysis with Python lecture in AI, food, health, biology
and chemistry contexts. It does not represent real products, validated
experimental measurements, clinical evidence, food-safety thresholds or
regulatory advice.

The dataset represents a small imagined storage experiment:

- 3 juice types: orange, apple and berry
- 3 storage temperatures: 4, 20 and 35 °C
- 4 storage days: 0, 2, 4 and 6
- 3 repeated batches for every condition
- 108 rows and 9 columns in total

The values are generated by `generate_fruit_juice_storage.py` with a
deterministic random number generator. The formulas are designed to make
beginner-friendly patterns visible: vitamin C decreases with storage time and
temperature, microbial load increases with storage time and temperature, and
turbidity is positively related to microbial load. These patterns are
simulations, not scientific conclusions.

For teaching data cleaning, the file deliberately contains exactly:

- 2 missing `pH` measurements (`S011` and `S071`)
- 2 missing `turbidity_NTU` measurements (`S026` and `S091`)
- 1 high microbial-load teaching outlier: `S108` has
  `microbial_load_log10 = 7.80`

The turbidity value for `S108` is recalculated after the microbial-load
outlier is inserted, using the same turbidity formula and its deterministic
measurement-noise term. This keeps the intended positive relationship between
microbial load and turbidity available for an optional extension. It is not a
conclusion of the lecture's vitamin-C-versus-turbidity scatter plot.

`write_dataset(path)` interprets a relative path from Python's current working
directory (`Path.cwd()`), not from the location of the generator file. To
regenerate the published CSV safely, first move to the project root and then
run:

```bash
cd /path/to/python-data-analysis
python data/generate_fruit_juice_storage.py
```

The generator can also be imported in a notebook or script launched from the
project root:

```python
from data.generate_fruit_juice_storage import build_dataset, write_dataset
from pathlib import Path

df = build_dataset(seed=42)
project_root = Path.cwd()
write_dataset(project_root / "data" / "fruit_juice_storage.csv")
```

Here, `Path.cwd()` is reliable only because the notebook or script is being
run from the project root. If the notebook is stored or launched from another
directory, replace the placeholder below with the actual absolute project
path, add that root to `sys.path` before importing, and pass paths based on
that root:

```python
from pathlib import Path
import sys

project_root = Path("/absolute/path/to/python-data-analysis")
sys.path.insert(0, str(project_root))

from data.generate_fruit_juice_storage import build_dataset, write_dataset

df = build_dataset(seed=42)
write_dataset(project_root / "data" / "fruit_juice_storage.csv")
```

The same explicit-root pattern avoids accidentally creating or overwriting a
`data/` directory relative to an unrelated notebook working directory.

## Column overview

The nine columns are:

| Column | Meaning |
|---|---|
| `sample_id` | Unique sample label |
| `juice_type` | `orange`, `apple` or `berry` |
| `storage_temp_C` | Storage temperature in °C |
| `storage_day` | Storage time in days |
| `batch` | Repeated batch number, 1–3 |
| `vitamin_c_mg_per_100ml` | Simulated vitamin C in mg per 100 mL |
| `pH` | Simulated pH measurement |
| `microbial_load_log10` | Teaching representation of log10 CFU/mL; not a real threshold |
| `turbidity_NTU` | Simulated turbidity in NTU |

For definitions, example rows, missing values and the S108 teaching outlier,
see [`docs/fruit-juice-data-dictionary.md`](../docs/fruit-juice-data-dictionary.md).

## Run the analysis demonstration

From the project root, run:

```bash
python code/fruit_juice_analysis_demo.py
```

The script locates the CSV relative to the project and writes three PNG files
to `outputs/`: `vitamin_c_over_time.png`,
`microbial_load_by_temperature.png` and `vitamin_c_vs_turbidity.png`.

In the lecture, `clean_df` is the core `isna()`/`dropna()` demonstration: it
is a copy with rows missing either `pH` or `turbidity_NTU` removed. It is not
used for the summary table. `main()` and the plotting calls use `raw_df`; each
plot then drops only the columns required by that particular plot. This keeps
missing pH values from unnecessarily removing vitamin-C observations.

The `S108` high microbial-load value is an optional teaching extension. If
time remains, inspect it with `raw_df[raw_df["sample_id"] == "S108"]`; it is
not part of the main lecture route.

The generator and `write_dataset(path)` use paths relative to Python's
**current working directory** when a relative path is supplied. For that
reason, run the commands above from the project root, or pass an explicit
`Path` when working from a notebook in another folder.

All values remain synthetic and teaching-only. The file must not be used to
make real clinical, food-safety, regulatory or scientific decisions.
